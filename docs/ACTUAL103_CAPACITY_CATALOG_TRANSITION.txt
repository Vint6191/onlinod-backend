ONLINOD — ACTUAL103 / CAPACITY CATALOG TRANSITION — 2026-10-01

Причина
Analytics/Traffic V1 убрал traffic_sources_scan из текущего job-catalog, но
ProviderCapacityProjectionState.jobKeys сохранил каталог из 12 ключей. Правильная
строгая проверка publisher останавливала его с CAPACITY_PROJECTION_CATALOG_CHANGED.
Лог пользователя подтверждает: миграции V1 успешно применены; ошибка возникла уже
в scheduler/maintenance. Виноват отсутствующий переход persisted catalog в V1.

Решение
Новая forward migration 20261001003000_capacity_catalog_traffic_retirement_v1
принимает только точный старый каталог (12) или уже целевой (11). Произвольное
изменение состава, дубликат, другое поколение и отсутствующий state не исправляются
автоматически. Runtime и deploy postflight используют одну функцию проверки.
Обычный prisma:migrate теперь проверяет каталог после применения SQL и до успеха
build. На каждом deploy выводится CAPACITY_PROJECTION_CATALOG_PASS / jobKeys:11.

Атомарность и rollout
Миграция берёт тот же advisory lock, затем singleton row lock, что и publisher.
Старый уже начатый batch заканчивается до перехода. Новый batch старого каталога
отклоняется до чтения/удаления очереди. Каталог, revision и conservative snapshot
меняются одним commit через существующий publication fence. Неуспешный переход
откатывает всё. Повтор на целевом каталоге ничего не меняет.
Снижение допустимой периодической нагрузки не удаляет canonical jobs или demand.

Прогресс и масштаб
Это строго вычитательный переход: формулы directory, FanData и остальных job
classes не меняются. Fixed-catalog read перестаёт включать retired bucket.
Накопленные source cursors, complete flags и dirty signals остаются на месте;
повторного обхода JobInstance history или большого UPDATE/DELETE в миграции нет.
Существующий Traffic RETIRE lane отменяет старые задания порциями до 100, а
canonical dirty triggers обеспечивают обычное вычитание их contributions.
Текущая очередь capacity обрабатывается прежними ограниченными batch 3..128.
Незавершённый bootstrap продолжает прежний проход. Новые canonical изменения
позади cursor по-прежнему попадают в durable dirty queue.
Будущее ДОБАВЛЕНИЕ job key или изменение его формулы требует другого явного
перехода и собственного bounded backfill. Данная миграция для этого не подходит.

Границы доказательства
Локальные PGlite SQL proofs проверяют реальные таблицы, triggers, Prisma/services,
rollback, повторное применение и populated upgrade. Это одна физическая сессия.
Реальные interleavings нескольких PostgreSQL connections, многорепличный rollout
и нагрузка множества агентств с тысячами creators остаются OPEN.
Нет изменений provider rate gate, Desktop runtime, schema.prisma и зависимостей.
Все ранее выданные SQL migrations неизменны. Phase7 BRIDGE сохраняется.
SOURCE CLOSED / SCALE CLOSED всего Analytics/Traffic и проекта не объявляются.
