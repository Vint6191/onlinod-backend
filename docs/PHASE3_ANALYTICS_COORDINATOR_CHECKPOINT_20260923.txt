   It now processes one bounded page: default 25, hard maximum 100 creators,
   plus one lookahead row; a cooperative 5-second budget stops before starting
   another creator. One in-flight operation can exceed this budget.
2. Durable yield clears ownership, persists the last fully planned creator,
   preserves the claimed revision and leaves completion pending. Another worker
   resumes that revision/cursor. Same-agency claims are excluded for the remainder
   of a pulse; ready-time ordering rotates continuations behind older due work.
   requestedAt retains user-request meaning; nextAttemptAt is durable eligibility.
3. Transient failure previously cleared claimedRevision and lost in-memory progress.
   Error settlement now persists completed creator progress and the revision;
   backoff/retry resumes the unfinished creator. Existing exact-window planning
   remains canonical; partial work can be replayed idempotently.
4. Requested creatorIds were parsed but ignored. Execution now intersects requested
   IDs with current member authority and agency/lifecycle filters. Scope cannot
   broaden to every agency creator. accessEpoch is checked before each creator.
5. Home admission accepts only existing Home ranges. Persisted invalid ranges,
   future end dates and more than 180 covered days are quarantined before creator
   enumeration. Corrupt scope has an explicit terminal contract error code.
6. Yield/error/completion still lock the demand row, then sample DB time and
   check live token/revision/expiry. A newer request revision outranks old yield,
   success, failure or cancellation and starts with a clean cursor.
7. Scheduler timer now handles fulfilled ok:false as well as rejection. Existing
   admin scheduler health includes analyticsDemand and reports DEGRADED while it
   fails; healthy recurring ticks and overlap skips cannot hide that failure.
   Error payloads are bounded; unchanged repeated errors log at most once/minute.
   Every finished attempt still updates health. Successful processing clears it.
