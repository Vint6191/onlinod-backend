A37-R2 CAUSAL SOURCE FINDINGS
A. Agency/shard dispatch sorted mutable locators and then locked them using
   FOR UPDATE SKIP LOCKED, without retaining the snapshot revision. A row can
   change between its sorted observation and lock acquisition; accepting its
   replacement revision can service it at its obsolete position.
B. Reservation recorded a clock sampled before authorization/query execution.
   Delayed transactions could publish an older timestamp. Reconciliation also
   used only due time and the supplied touch time, discarding its own newer
   lastSelectedAt/lastClaimedAt when a stale or null touch arrived.
C. A missed/contended locator immediately allowed physical fallback. Existing
   busy locators and genuinely missing projection rows were conflated, allowing
   a worker to bypass the normal fair dispatch hierarchy under contention.
D. Six settlement operations sampled DB time before waiting for their DWI row.
   An expired owner could heartbeat/ack/block/retry/save/yield using that stale
   time. A37-R1 had corrected planning commit checks but not these transitions.
PostgreSQL reference for mutable ordering and row-lock semantics:
https://www.postgresql.org/docs/current/sql-select.html#SQL-FOR-UPDATE-SHARE

COHESIVE IMPLEMENTATION
1. Both broad Agency and shard reservations materialize at most 128 ordered
   candidate identities and revisions using existing dispatch indexes. The
   lock/join requires that same revision, and the final UPDATE repeats the CAS.
   A peer's replacement revision cannot inherit the old sorted position.
2. Reservation samples database time after obtaining the candidate lock and
   preserves the existing selection watermark. No process clock is authority.
3. A bounded indexed due-locator probe distinguishes contention from absence.
   Contention retries only within the existing finite tranche budget. Missing
   locators retain the indexed physical-DWI repair path; canonical tasks remain
   the execution authority. No global lock or all-history scan is introduced.
4. Partition, shard and Agency reconciliation preserve their own monotonic
   selection watermark within a generation, including old/null touch inputs.
   New generations reset that watermark. Revision-CAS and the established
   DWI -> partition -> shard -> Agency ordering remain in place.
5. heartbeatDomainWorkClaim, ackDomainWorkClaim, blockDomainWorkClaim,
   failDomainWorkClaim, saveDomainWorkProgress and yieldDomainWorkClaim all use
   lockDomainWorkClaimForCommit before testing time or changing work. Blocking
   retains dependency -> DWI order so dependency publication cannot invert it.
   Owner/fence/claimedRevision/generation/live-expiry must all still match.
6. Test adapters now recognize the exact standalone DB clock SELECT. They must
   not mistake a reservation SQL statement containing clock_timestamp for that
   SELECT. No production time guard or physical assertion was relaxed.
