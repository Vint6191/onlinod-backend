3. ВЛАДЕЛЕЦ КОМАНД БЕЗОПАСНОСТИ АККАУНТА

Новый специализированный endpoint POST /api/account-security/commands/v1 и /cancel.
Пять строгих действий: account.password, account.logoutDevice, account.logoutOthers,
account.revokeSession, account.revokeOthers. Старый общий management transport
по-прежнему обслуживает свои 13 действий; секрет пароля туда не попадает.

Применена существующая таблица ManagementCommandReceipt D6 без новой миграции.
Отдельное пространство account_security_v1_ исключает пересечение идентификаторов
с другими management-командами. UUID + SHA256 fingerprint исходного действия,
target и payload; UUID входит в digest. В receipt нет plaintext пароля, bcrypt hash
или refresh/access token. Для этого домена reference хранит малый результат
исторического события: actor/устройство, исходная login lineage, counts и flags.
Это не снимок актуального пароля/всех сессий. Replay подтверждает прежний commit.

При новом исполнении payload связывается с deviceId и authorizationSessionId из
подписанного access JWT. Старая ещё не выполненная команда не исполняется под
новым login: ACCOUNT_SECURITY_ORIGIN_CHANGED; её можно отменить и создать новое
осознанное действие. Уже выполненную команду новый login того же account/agency
может подтвердить без повторного эффекта. Cancel-before-execute пишет ABANDONED;
commit-before-cancel подтверждает commit и не возвращает прежний пароль/сессии.

Внутри одного kernel root: общий Agency lifecycle barrier, mutex команды,
authorization-user lock, User FOR UPDATE, актуальный User/Member/epoch и живая
подписанная login lineage, изменение домена, required audit, receipt. Login,
refresh, reset, logout используют тот же account lock. Результат не признаётся
по request-time auth. Проверка actor и его текущей lineage нужна и при replay/cancel.
Владелец не требуется для собственного пароля/выхода: любой живой участник меняет
только свой аккаунт. Один OWNER агентства не нарушается.

bcrypt выполняется до длинной SQL-транзакции. Прочитанный credential hash ещё раз
сравнивается под User lock; чужой password change/reset не перезаписывается старой
проверкой. Наличие receipt проверяется раньше повторной проверки старого пароля.
Если commit произошёл параллельно bcrypt, receipt внутри root имеет приоритет
перед сохранённой ошибкой подготовки. Повтор транзакции с внешними эффектами
не вводился. Пароль и audit/receipt атомарны; требование audit обязательно.

4. СПИСОК УСТРОЙСТВ И ВЕРСИЯ ПОКАЗАННОГО НАМЕРЕНИЯ

Account settings выдаёт revision каждой группы устройства/legacy session и
otherDevicesRevision. Snapshot состоит из agency/device/login lineage, сортируется
и дедуплицируется. Обычная refresh rotation сохраняет revision; новый login меняет
её. Для NULL-lineage строк используется точный row ID: выдуманной семьи токенов нет.
lastUsedAt, worker heartbeat и смена срока при refresh не ломают версию редактора.

Перед отзывом выбранных входов сервер повторно вычисляет этот snapshot под общим
account lock. Новое устройство/новый login не отзывается старым delayed intent:
возвращается ACCOUNT_SECURITY_SESSION_CHANGED без частичного logout.
Account logout остаётся межагентским по самому user: выбранное устройство своего
аккаунта отзывается во всех его агентствах, другие пользователи не затрагиваются.
Все UPDATE ограничены живыми строками и точными id выбранного snapshot.

Перечисление live RefreshSession ограничено 2048 строками на аккаунт; 2049-я
вызывает явную ошибку и не даёт выполнить усечённый logout. Это локальный предел
операции одного аккаунта, не утверждение о пределе агентств или моделей платформы.

5. ТОКЕНЫ LOGIN И PASSWORD RESET

/api/auth/logout и containment при refresh-token reuse теперь отзывают только
исходную user/agency/device/authorizationSessionId. Поздний старый токен не получает
власть над новым login. Ротированный токен всё ещё может прекратить собственную
lineage. После account lock исходная строка перечитывается, в том числе после
legacy adoption; request-time snapshot не определяет более широкое действие.

NULL-lineage refresh token может отозвать только собственную строку. Исторической
семьи у него нет; account/device-wide fallback удалён. Полная family-reuse защита
возможна для lineage-aware login. Не выдавать это за реконструкцию legacy family.
Logout всех логических входов устройства принадлежит явной security-команде.

authRequired отклоняет access JWT без device binding: такой JWT не мог быть
немедленно ограничен device logout. Код AUTH_DEVICE_BOUND_SESSION_REQUIRED требует
повторного входа с актуального Desktop. Device-bound legacy NULL-lineage refresh
сохраняет прежний upgrade/adoption путь; новые security-команды требуют явной
lineage. Никакие WorkerDevice, AMK/CDK и криптопривязки logout не удаляет.

Reset-token потребляется только после повторных usedAt/expiresAt проверок под
User lock и по времени БД. Условный updateMany дополнительно проверяет usedAt=null
и expiresAt>now. Пароль, потребление reset-token, закрытие всех прочих reset-tokens,
sessionsRevokedAt и отзыв всех live refresh sessions — одна транзакция.
Два конкурирующих запроса reset не могут оба записать пароль. Ошибка записи User
откатывает потребление и отзыв. Lost reset response не воспроизводится как новый
успех: TOKEN_USED требует проверить вход с уже заданным паролем либо новый reset.

In-app password change тоже закрывает все старые неиспользованные reset-tokens.
Выдача reset-token теперь сериализована тем же User lock, проверяет актуальную
активность и исходный credential hash, заменяет старые tokens атомарно, использует
DB clock для срока. Отправка email остаётся после commit и отдельным внешним
эффектом: durable mail outbox/idempotency provider здесь не заявляется. Два явных
запроса выдачи могут отправить два письма, но текущий token останется один.
Email verification, полный login/registration lifecycle остаются вне закрытия D8.

6. DESKTOP / UI И СЕКРЕТНЫЙ ЖУРНАЛ

Новый AccountSecurityCommandTransport использует отдельный
account-security-pending-v1.json. Весь журнал зашифрован Electron safeStorage;
недоступный keychain или basic_text останавливает действие ДО HTTP. Нет plaintext
fallback, пароли/хеши намерения не попадают в открытые labels или pending RPC.
Коррупция/decrypt failure не очищает pending intent. AtomicJsonStore сохраняет
fsync и восстановление Windows .bak. Ограничения: 32 записи / 4 MiB encrypted
journal, 4 KiB payload, один unresolved security slot на backend/user/agency.

DurableCommandTransport получил optional journal codec. Секретные payload допускает
только явно защищённый transport; обычные Team/Message Library/Management журналы
сохраняют прежнее поведение и дополнительно запрещают currentPassword/newPassword.
Регрессионные проверки старых команд прошли. Не вводится общий обход запрета секретов.

Изначальный UUID, payload и origin login сохраняются ДО запроса, остаются после
HTTP/IPC loss и Main restart до ACK. Before/after CONTROL permit и local incarnation
отсекают поздний ответ. Ответ проверяется по action, user, device, origin lineage,
counts/flags, включая невозможность self logout для logoutOthers/password.

Подтверждённый self logout сначала подтверждает запись локально, затем очищает
текущий authStore. Replay старого self logout после нового входа никогда не очищает
новую сессию. Если reply пришёл после смены сессии, он не получает ACK как текущий.
Сбой ACK сохраняет возможность дальнейшего восстановления.

Settings/Main/typed RPC/UI связаны целиком: password, logoutDevice, logoutOtherDevices
вызывают новый owner; устройства передают показанную revision. Совместимые старые
Main session methods тоже направлены в owner, хотя активный UI device-oriented.
Панель восстановления Settings показывает отдельную группу account security с
Recover/Cancel. UI использует ACK helper; self logout уже завершает ACK в Main.
Native Electron/safeStorage/реальная OS keychain здесь не запускались: codec tests
используют управляемый криптографический адаптер, не выдают его за физическую ОС.

7. CUTOVER И СОВМЕСТИМОСТЬ

Пять старых маршрутов закрыты ранним 410 до handler:
POST /api/settings/account/password
DELETE /api/settings/account/devices/:deviceId
POST /api/settings/account/devices/logout-others
DELETE /api/settings/account/sessions/:sessionId
POST /api/settings/account/sessions/revoke-others
Case-insensitive и trailing slash проверены. Avatar, forgot-password, Telegram
и reads не задеты gateway. Нет silent fallback на старую незащищённую запись.

Route manifest учитывает новый owner: 52 production families. Anti-map теперь
классифицирует 19 refreshSession.updateMany: новый command writer, перенесённый
reset writer, delegated bounded lineage revocation. Устаревшая source-template
проверка auth lock order обновлена до действующих helper/Admin owner; это не
новое изменение админского кода. Старые bodies Settings за410 сохранены для
исторической совместимости исходников, публичным write path больше не являются.

Схема D8 побайтово равна D7. Новых migrations нет; существующая D6 receipt migration
входит в накопительный Backend. Backend/Desktop требуют согласованного cutover.
Старый Desktop на указанных путях получит410; unbound JWT потребует новый вход.
Это причина не ставить одну сторону отдельно. Установка всего пакета пока не одобрена.
