СТАВИТЬ: оба патча. Backend сначала, затем Desktop.
Основа: Desktop 156.zip и Backend onlinod-backend-main - 2026-10-14T180040.693.zip.
Это changed-only патчи: файлы из них распаковать поверх соответствующего проекта.

1. Закрыть Desktop. Применить Backend-патч к Backend и выполнить обычный deploy.
   Новых зависимостей и миграций в этом патче нет. Базу не сбрасывать.
2. Применить Desktop-патч к корню Desktop с заменой файлов.
3. В корне Desktop запустить APPLY_CAMPAIGNS_156.cmd.
   Он проверит источник и собранный renderer, затем удалит только два старых
   файла renderer с подтверждёнными SHA-256. Это нужно, поскольку ZIP-overlay
   не умеет удалять заменённые файлы с хешами в именах. Повторный запуск безопасен.
   Альтернатива в терминале: node scripts/finish-campaigns-156.mjs.
   При сообщении о неполной/иной сборке выполнить штатный npm run build.
4. Запустить Desktop, открыть Campaigns и нажать RETRY FAILED REFRESH.
   Это восстановит существующий карантин FanData. Полный обход Campaigns
   для этого не требуется. Недоступные профили останутся с неизвестной суммой;
   прежние сохранённые деньги не обнуляются. Ошибки сети/авторизации повторяются.

Для следующей передачи актуала: PACK_ACTUAL.cmd или npm run pack:actual.
Отправлять новый ONLINOD_Actual_*.zip из exports, а не архив всей рабочей папки.
Архив содержит исходники и lock-файл. После распаковки в новый каталог:
npm ci, затем npm run build. Сессии, локальные данные и зависимости не входят.
Упаковщик ничего из рабочей папки не удаляет.
